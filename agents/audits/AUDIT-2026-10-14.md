## Ranked findings

### P0 — Unauthenticated OpenAI routes on the Express gateway

`POST /api/ai/chat` and `POST /api/ai/quick-answer` are registered on Express, not FastAPI, and have no auth check. An empty JSON body stops at validation:

- `POST https://founderconsole.ai/api/ai/chat` `{}` → **400** `{"error":"Messages array is required"}`
- `POST https://founderconsole.ai/api/ai/quick-answer` `{}` → **400** `{"error":"Question is required"}`

A `messages` array (or a `question` string) reaches `openai.chat.completions.create` with model `gpt-5` (`server/replit_integrations/chat/routes.ts:31-98` and `:120-146`). `LOCAL_API_PREFIXES` keeps `/ai/` off the FastAPI proxy (`server/index.ts:729-734`), so FastAPI auth and its rate limiter never see it. Whether `OPENAI_API_KEY` / `AI_INTEGRATIONS_OPENAI_API_KEY` is set in production was **not** tested, because that would spend money. If the key is set, this is an open paid endpoint. Image generation (`registerImageRoutes`) is not mounted: `POST /api/generate-image` `{}` → **404**.

### P1 — Resend webhooks accept unsigned events

Two receivers, neither verifies a Svix signature before writing:

- `POST /api/notifications/resend-webhook` has no auth and no signature check (`server/api/notifications.py:198-209`). It calls `classify_email_event` and returns `{"status":"ok"}`.
- `POST /api/email-tracking/webhooks/resend` defines `_verify_resend_signature` (`server/api/email_tracking.py:23-36`) and never calls it. If `RESEND_WEBHOOK_SECRET` is empty, the helper returns `True`. If the secret is set, the handler only rejects a *missing* header (`:50-51`), then parses the body and upserts `EmailEvent`.

Not probed with a body, because a well-formed payload would write a row. Open, unmerged: [#77](https://github.com/predixen/founderconsole/pull/77) (fail closed) and [#53](https://github.com/predixen/founderconsole/pull/53) (Svix verify).

### P1 — `/unsubscribe` is not an unsubscribe

Email footers link to `/unsubscribe`. The route is a client-side redirect to `/settings`, which requires a session (`client/src/App.tsx:520-524`). A logged-out recipient gets the auth wall, not a one-click opt-out. `List-Unsubscribe` appears only in `server/email/send_update_v22.py`, not in `server/email/service.py`. Draft [#60](https://github.com/predixen/founderconsole/pull/60) adds a real unsubscribe path and is not merged.

### P1 — Login treats a failed company fetch as “no company”

After a successful login, `api.companies.list()` errors are swallowed and an empty list sends a non-admin to `/onboarding` (`client/src/pages/auth.tsx:175-188`). A blip on that GET looks like a brand-new account. Register itself does surface `ApiError` (`:233-242`). Forgot-password sets the “sent” state without checking `res.ok` (`:146-154`), so a 500 looks like success.

### P1 — Trailing-slash redirect points at the internal FastAPI bind

`GET https://founderconsole.ai/api/templates` (no slash) → **307** `Location: https://localhost:8001/templates/`. The same response carries FastAPI’s CSP, not Express’s. `GET /api/templates/` → **401**. Clients and browsers that follow the redirect never reach the app. The proxy does not rewrite `Location`.

### P1 — Server events will not join the browser person

Browser `identifyUser` uses `String(userId)` (`client/src/lib/posthog.ts:136-141`). Server `signup_completed` uses `user:{id}` (`server/services/activation.py:41-46`). Server `lead_captured` uses `lead:{sha256(email)[:32]}` (`server/api/leads.py:97-125`) and does not alias the browser id. The client still fires `lead_captured` via `trackFunnel` after a 2xx (`client/src/pages/runway-calculator.tsx:168-171`), so attribution depends on the browser SDK loading. `server/services/posthog.py:27-32` prefers `POSTHOG_KEY` / `POSTHOG_PROJECT_API_KEY` over the known-good default; a stale env key would drop server events only. That env value was not readable from here.

### P1 — Stripe webhook acks checkouts it cannot attach

`payments_enabled` is **true** on `GET /api/billing/plans` (free 0, starter 29, growth 49, scale 99). `POST /api/billing/webhook` with `{}` → **400** `Invalid signature` (`server/api/billing.py:242-254`, `server/core/stripe_billing.py:172-176`). If `checkout.session.completed` verifies but `user_id` cannot be resolved, the handler logs and still returns `{"received": true}` (`server/api/billing.py:275-278` and `:307`). Stripe will not retry, so the subscription is never written.

## Core flows (code)

**Signup / login.** Register and login toasts surface `ApiError` and `Failed to fetch` (`client/src/pages/auth.tsx:190-199`, `:233-242`). Register then `identifyUser` + `trackSignup` (`signup_completed` and GA4 `sign_up`) and sends the user to `/onboarding` (`:227-232`). Server emits `signup_completed` only on user creation, email and Google (`server/api/auth.py` via `emit_signup_completed`, `server/api/oauth.py`). OAuth errors map to toasts (`auth.tsx:109-124`). The company-list hole is the P1 above. `/signup` is a marketing page whose CTA goes to `/auth?tab=register`; SSR is present. `/login` is not an HTTP redirect.

**Onboarding.** Public step list is static (`server/api/onboarding.py:5-15`). The app route requires auth. Optional financials were fixed earlier (`ce795209`, `cbc1476e`); this pass did not re-run the UI.

**Truth Scan / activation.** `founder_activated` is server-side and skips sample companies (`server/services/activation.py:22-33`). Client `trackFounderActivated` requires `is_sample === false` and a localStorage latch (`client/src/lib/funnel.ts:33-51`). Copilot calls `apply_not_available_guard` after generation (`server/api/copilot.py:1341-1354`). The guard refuses only when the answer states a figure for a missing metric (`server/copilot/trust.py:823-855`), so “how do I reduce churn?” can still be qualitative. `POST /api/companies/1/chat` without a session is 401.

**Runway calculator + leads.** The form posts email plus runway fields (`client/src/pages/runway-calculator.tsx:147-176`). Non-OK throws into `sendState = "error"` without a toast. Server commits first, then queues `lead_captured` and the Resend runway email only when `runway_months` and `runway_date` are set (`server/api/leads.py:174-181`). DB errors become 503, not a stack trace (`:168-172`). `useViewedOnce("lead_form_viewed", { location: "runway-calculator" })` fires PostHog only, once, at half visibility (`client/src/hooks/use-viewed-once.ts:16-34`). Funnel names in code are `signup_view`, `signup_start`, `signup_completed`, `sign_up`, `lead_form_viewed`, `lead_captured`, `founder_activated` — not `signup_started`.

**Email.** Resend is the sender (`server/email/service.py:227-254`). Failures return `{success: false}` and do not raise. Unsubscribe gap is the P1 above.

**Stripe.** Checkout creation was not called. Signature rejection and the unresolved-user ack are above. Paywall is env-gated (`PAYWALL_ENABLED`); not observable from outside.

## Security headers and CORS

Express document CSP allows `'unsafe-inline'` and `'unsafe-eval'` in `script-src` (`server/index.ts:60`). That is what the browser enforces. FastAPI adds a second CSP on proxied responses (no `unsafe-eval`, includes Sentry and `api.openai.com`, omits gtag). CORS allow-list rejects `https://evil.example` and reflects `https://founderconsole.ai` with credentials. `Access-Control-Allow-Credentials: true` is also present when `Allow-Origin` is absent; browsers will not treat that as a credentialed cross-origin success.
