## 🔴 BUG 1: NLP SCENARIO PARSING — BROKEN ACROSS ALL 4 ROUNDS

### The problem
When users type natural language scenarios in the /simulate page, the simulation engine does NOT extract or apply any variable changes. Every simulation shows **"No changes from baseline"** in the "Scenario Inputs vs Baseline" section. The Monte Carlo runs on unmodified baseline data regardless of what the user types.

### Tested scenarios that all failed (20+ times across 4 rounds):
- "What happens if our shipping costs increase 25% due to fuel price hikes?" → No changes
- "What happens if COD return rates spike from 15% to 35%?" → No changes
- "What happens if a competitor launches free shipping and we lose 20% of customers?" → No changes
- "What happens if we cut our burn rate by 30%?" → No changes
- All produce identical P50 runway (~51.1-51.9 months) confirming baseline-only execution

### The only things that DO work:
- Quick scenario pills ("Cut marketing 30%", "Raise prices 20%") — these bypass the NLP and directly set variables
- The "Adjust Variables Manually" button — directly sets slider values

### Root cause
The function that converts user text → simulation variable changes is either:
(a) Not being called at all
(b) Failing silently and defaulting to baseline
(c) Using a keyword matcher that's too narrow

```python
import json
from openai import AsyncOpenAI

client = AsyncOpenAI()

PARSE_PROMPT = """You are a financial scenario parser for a startup simulation engine.

The user described a scenario. Extract the specific variable changes to apply to a Monte Carlo simulation.

CURRENT COMPANY BASELINE:
- Monthly Revenue (MRR): ${mrr}
- Monthly Burn Rate: ${burn}
- Cash Balance: ${cash}
- Growth Rate: {growth}%
- Churn Rate: {churn}%
- Gross Margin: {margin}%
- LTV:CAC Ratio: {ltv_cac}x
- Customer Count: {customers}

AVAILABLE VARIABLES YOU CAN MODIFY:
1. revenue_growth_rate_change: percentage point change (e.g., +10 means growth goes from 0% to 10%)
2. burn_rate_change_pct: percentage change to burn (e.g., -30 means 30% reduction, +25 means 25% increase)
3. churn_rate_change: percentage point change (e.g., +2 means churn goes from 3.2% to 5.2%)
4. gross_margin_change: percentage point change (e.g., -15 means margin drops from 82% to 67%)
5. customer_count_change_pct: percentage change in customers (e.g., -20 means lose 20% of customers)
6. fundraise_amount: dollar amount of new funding (e.g., 5000000 for $5M raise)
7. opex_change_pct: percentage change in operating expenses (e.g., +25 means opex goes up 25%)
8. headcount_change_pct: percentage change in team size (e.g., -10 means reduce headcount 10%)

MAPPING RULES:
- "shipping costs increase 25%" → opex_change_pct: +25
- "lose 20% of customers" → customer_count_change_pct: -20 AND revenue_growth_rate_change: -20
- "COD returns spike to 35%" → gross_margin_change: -15 (returns eat into margin) AND opex_change_pct: +10 (reverse logistics costs)
- "competitor launches free shipping" → churn_rate_change: +3 AND revenue_growth_rate_change: -10
- "cut burn by 30%" → burn_rate_change_pct: -30
- "hire 5 engineers" → burn_rate_change_pct: +5 AND headcount_change_pct: +5
- "raise prices 20%" → revenue_growth_rate_change: +15 AND churn_rate_change: +1
- "raise $5M Series A" → fundraise_amount: 5000000
- NEGATIVE scenarios MUST produce negative variable changes
- POSITIVE scenarios MUST produce positive variable changes
- You can modify MULTIPLE variables for one scenario

Return ONLY valid JSON:
{
  "variables": {
    "variable_name": numeric_value,
    ...
  },
  "summary": "one-line description of what changes were applied",
  "confidence": "high" | "medium" | "low"
}

If the scenario is unclear, still make your best guess — do NOT return empty variables."""

async def parse_scenario_with_llm(user_text: str, company_data: dict) -> dict:
    """Parse natural language scenario into simulation variable changes using GPT-4o."""

    prompt = PARSE_PROMPT.format(
        mrr=f"{company_data['mrr']:,.0f}",
        burn=f"{abs(company_data['monthly_burn']):,.0f}",
        cash=f"{company_data['cash_balance']:,.0f}",
        growth=company_data.get('growth_rate', 0),
        churn=company_data.get('churn_rate', 3.2),
        margin=company_data.get('gross_margin', 82.4),
        ltv_cac=company_data.get('ltv_cac_ratio', 10),
        customers=company_data.get('customer_count', 150),
    )

    try:
        response = await client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": prompt},
                {"role": "user", "content": user_text}
            ],
            response_format={"type": "json_object"},
            temperature=0.1,
            max_tokens=500,
        )
        result = json.loads(response.choices[0].message.content)

        # Validate that at least one variable was extracted
        if not result.get("variables") or len(result["variables"]) == 0:
            # Fallback: try a more aggressive extraction
            return await _fallback_parse(user_text, company_data)

        return result

    except Exception as e:
        print(f"LLM parsing failed: {e}")
        return {"variables": {}, "summary": "Could not parse scenario", "confidence": "low"}


async def _fallback_parse(user_text: str, company_data: dict) -> dict:
    """Fallback: simple keyword matching if LLM fails."""
    text = user_text.lower()
    variables = {}

    # Cost increases
    if any(w in text for w in ["shipping cost", "logistics cost", "carrier rate", "fuel price", "fulfillment cost"]):
        # Extract percentage if present
        import re
        pct_match = re.search(r'(\d+)%', text)
        pct = int(pct_match.group(1)) if pct_match else 20
        if any(w in text for w in ["increase", "rise", "hike", "spike", "go up"]):
            variables["opex_change_pct"] = pct
        elif any(w in text for w in ["decrease", "reduce", "cut", "drop"]):
            variables["opex_change_pct"] = -pct

    # Customer loss / churn
    if any(w in text for w in ["lose customer", "customer loss", "customers leave", "churn increase"]):
        pct_match = re.search(r'(\d+)%', text)
        pct = int(pct_match.group(1)) if pct_match else 15
        variables["customer_count_change_pct"] = -pct
        variables["revenue_growth_rate_change"] = -pct

    # Competitor
    if "competitor" in text:
        variables["churn_rate_change"] = variables.get("churn_rate_change", 0) + 3
        variables["revenue_growth_rate_change"] = variables.get("revenue_growth_rate_change", 0) - 10

    # Returns / COD
    if any(w in text for w in ["return rate", "cod return", "rto", "reverse logistics"]):
        pct_match = re.search(r'(\d+)%', text)
        if pct_match:
            variables["gross_margin_change"] = -int(pct_match.group(1)) // 2
        else:
            variables["gross_margin_change"] = -10
        variables["opex_change_pct"] = variables.get("opex_change_pct", 0) + 10

    # Burn changes
    if any(w in text for w in ["cut burn", "reduce burn", "lower burn"]):
        pct_match = re.search(r'(\d+)%', text)
        pct = int(pct_match.group(1)) if pct_match else 20
        variables["burn_rate_change_pct"] = -pct

    if any(w in text for w in ["increase burn", "more spending"]):
        pct_match = re.search(r'(\d+)%', text)
        pct = int(pct_match.group(1)) if pct_match else 20
        variables["burn_rate_change_pct"] = pct

    return {
        "variables": variables,
        "summary": f"Keyword extraction: {len(variables)} variables modified",
        "confidence": "medium" if variables else "low"
    }
```

### The problem

```python
def calculate_decision_score(
    p50_runway_after: float,
    p50_runway_before: float,
    survival_18m: float,
    p10_runway: float,
    scenario_direction: str = "neutral"  # "positive", "negative", "neutral"
) -> dict:
    """
    Calibrated 1-10 scoring with meaningful differentiation.

    Key principle: The score MUST reflect the CHANGE from baseline, not just absolute values.
    A company with 60mo runway getting a scenario that drops it to 40mo should score ~5,
    not 8 just because 40mo is still "fine."
    """

    # Calculate the magnitude of change
    runway_delta = p50_runway_after - p50_runway_before
    runway_change_pct = (runway_delta / max(p50_runway_before, 1)) * 100

    # Base score from survival probability
    if survival_18m >= 0.99:
        survival_score = 9
    elif survival_18m >= 0.95:
        survival_score = 7
    elif survival_18m >= 0.85:
        survival_score = 5
    elif survival_18m >= 0.70:
        survival_score = 3
    elif survival_18m >= 0.50:
        survival_score = 2
    else:
        survival_score = 1

    # Runway change score (-5 to +5)
    if runway_change_pct > 30:
        runway_score = 5
    elif runway_change_pct > 10:
        runway_score = 3
    elif runway_change_pct > 0:
        runway_score = 1
    elif runway_change_pct > -10:
        runway_score = -1
    elif runway_change_pct > -25:
        runway_score = -3
    elif runway_change_pct > -50:
        runway_score = -4
    else:
        runway_score = -5

    # P10 downside penalty
    p10_penalty = 0
    if p10_runway < 6:
        p10_penalty = -3
    elif p10_runway < 12:
        p10_penalty = -2
    elif p10_runway < 18:
        p10_penalty = -1

    # Composite score
    raw_score = (survival_score * 0.4) + ((runway_score + 5) * 0.4) + ((5 + p10_penalty) * 0.2)
    # Normalize to 1-10 scale
    final_score = max(1, min(10, round(raw_score)))

    # Verdict
    if final_score <= 3:
        verdict = "NO-GO"
        headline = "Don't do this."
    elif final_score <= 5:
        verdict = "CAUTION"
        headline = "Proceed with major modifications."
    elif final_score <= 7:
        verdict = "CONDITIONAL GO"
        headline = "Viable if key assumptions hold."
    else:
        verdict = "GO"
        headline = "The numbers support this move."

    return {
        "overall_score": final_score,
        "verdict": verdict,
        "headline": headline,
        "risk_score": min(10, max(1, 10 - abs(p10_penalty) * 2)),
        "reward_score": min(10, max(1, 5 + runway_score)),
        "capital_efficiency_score": min(10, max(1, survival_score)),
        "survival_impact_pct": round((survival_18m - 1.0) * 100, 1),
    }
```
